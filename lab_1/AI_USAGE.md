# AI Usage Report: Лабораторная работа №1

## Траектория и уровень
-   **Траектория:** AI и MLOps
-   **Уровень:** Основной
-   **Версия отчёта:** 1.0.0-lab-1

## Использование искусственного интеллекта

В рамках выполнения лабораторной работы инструменты генеративного ИИ использовались исключительно для вспомогательных задач. Доменная логика, архитектурные решения и код ядра системы разработаны самостоятельно.

### 1. Генерация синтетических данных
Для проверки CLI и сценариев валидации был сгенерирован файл `data/test_submissions.jsonl`. ИИ помог создать примеры, покрывающие граничные случаи: корректные записи, полные дубликаты, конфликты содержимого, нарушения схемы JSON и ошибки форматирования времени. Все данные были вручную верифицированы на соответствие спецификации.

### 2. Написание документации и отчётов
Черновики `README.md`, `AI_USAGE.md` и итогового отчёта подготовлены с помощью LLM для соблюдения единого стиля оформления. Финальная редакция выполнена самостоятельно с проверкой фактической точности всех утверждений и соответствия требованиям задания.

## Принципы работы с AI в проекте

-   **Доменная логика:** Модели данных, алгоритмы валидации, хеширования и обработки конфликтов разработаны без участия ИИ.
-   **Проверка результатов:** Весь код, предложенный ИИ, проходит обязательный code review и покрытие тестами перед интеграцией.
-   **Безопасность данных:** В запросы к ИИ не передавались реальные персональные данные студентов или конфиденциальная информация. Использовались только синтетические примеры.
-   **Критическое отношение:** Рекомендации ИИ рассматриваются как гипотезы, требующие экспериментальной проверки. Архитектурные решения принимаются на основе требований задания и лучших практик инженерии ПО.

## ЛР2: анализ сходства

При расширении проекта (ЛР2) ИИ использовался для:

-   черновиков `docs/LAB2.md`, `ОТЧЁТ_ЛР2.md` и раздела README;
-   обсуждения структуры учебного корпуса и граничных случаев;
-   проверки формулировок ограничений и оговорки «сходство ≠ вердикт».

Самостоятельно реализованы и проверены: протокол эксперимента, token baseline,
TF-IDF без утечки evaluation в fit, выбор порога только на tuning, признаки
пары, retrieval, разбор ошибок и логистическая регрессия. Метрики в отчёте
получены запуском кода на учебном корпусе, а не сгенерированы текстовой
моделью. Реальные студенческие данные не использовались.

На этапе Б ИИ помогал с черновиками описания review_required, матрицы ошибок,
профилирования и ML-эксперимента. Код обучения, расчёт метрик, bootstrap и CV
запускались и проверялись локально; выполнен MLflow-run с параметрами,
метриками и артефактами разбиения. JSON-fallback оставлен для окружений без
пакета. Для защиты добавлены версия отчёта, отпечатки конфигурации и
воспроизводимая демонстрация нового разрешённого шаблона. Отдельно проверены невалидный
результат модели (NaN/значение вне `[0, 1]` отклоняется) и побайтовая
воспроизводимость сохранённых артефактов эксперимента.

## ЛР3: ограниченный исполнитель

На этапе А ИИ помогал с черновиками `docs/LAB3.md`, `ОТЧЁТ_ЛР3.md` и
обсуждением контракта статусов, семантики очереди и кодов ошибок. Код
исполнителя, адаптеров и тестов проверен запуском `pytest`; бенчмарк потоков и
процессов выполнен локально, его результаты сохранены в
`artifacts/lab3/executor_benchmark.json`. Реальные персональные данные и
внешние модельные API не использовались.

## ЛР3, этап Б: хранение и API

На этапе Б ИИ помогал с черновиками `docs/LAB3_B.md`, `ОТЧЁТ_ЛР3.md` и
обсуждением схемы SQLite, атомарности `succeeded` + report, idempotency_key и
маршрутов FastAPI. Код хранилища, восстановление после рестарта, API и тесты
запускались локально. Внешние модельные API и реальные персональные данные не
использовались; ключ провайдера в ответы API не попадает.

## Ограничения текущего этапа

На данном этапе конфигурации режимов `ml` и `llm` в основном приложении возвращают детерминированный базовый результат. Реальные вызовы внешних моделей и больших языковых моделей не выполняются. Для ЛР2 реализованы retrieval кандидатов, детерминированная заглушка LLM-feedback и локальный ML-классификатор; интеграция внешних API запланирована на последующие этапы.
