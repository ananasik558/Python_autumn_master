# AI Usage Report: Лабораторная работа №1 (Этап А)

## Траектория и уровень
-   **Траектория:** AI и MLOops
-   **Уровень:** Основной
-   **Версия отчёта:** 1.0.0-stage-a

### 1. Генерация тестовых данных
Для проверки CLI-интерфейса и сценариев валидации был сгенерирован файл `data/test_submissions.jsonl`. QWEN помог создать синтетические примеры, покрывающие граничные случаи: корректные записи, полные дубликаты, конфликты содержимого, нарушения схемы JSON и ошибки форматирования времени. Все сгенерированные данные были вручную верифицированы на соответствие спецификации задания.

### 2. Написание документации
Черновики файлов `README.md` и настоящего отчёта были подготовлены с помощью LLM для соблюдения единого стиля оформления и полноты описания технических решений. Финальная редакция выполнена самостоятельно с проверкой фактической точности всех утверждений.

## Принципы работы с AI в проекте

-   **Доменная логика:** Модели данных, алгоритмы валидации, хеширования и обработки конфликтов разработаны самостоятельно. ИИ не генерировал код ядра системы.
-   **Проверка результатов:** Весь код, предложенный ИИ, проходит обязательный code review и покрытие тестами перед интеграцией.
-   **Безопасность данных:** В запросы к ИИ не передавались реальные персональные данные студентов, токены доступа или конфиденциальная информация. Использовались только синтетические примеры.
-   **Критическое отношение:** Рекомендации ИИ рассматриваются как гипотезы, требующие экспериментальной проверки. Архитектурные решения принимаются на основе требований задания и лучших практик инженерии ПО, а не на основании ответов модели.

## Ограничения текущего этапа

На Этапе А конфигурации режимов `ml` и `llm` возвращают детерминированный базовый результат. Реальные вызовы моделей машинного обучения или больших языковых моделей не выполняются. Интеграция внешних API и подготовка признаков для обучения запланированы на последующие этапы лабораторной работы.
