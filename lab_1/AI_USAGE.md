## Использование искусственного интеллекта

В рамках выполнения лабораторной работы инструменты генеративного ИИ использовались исключительно для вспомогательных задач. Доменная логика, архитектурные решения и код ядра системы разработаны самостоятельно.

### 1. Генерация синтетических данных
Для проверки CLI и сценариев валидации был сгенерирован файл `data/test_submissions.jsonl`. ИИ помог создать примеры, покрывающие граничные случаи: корректные записи, полные дубликаты, конфликты содержимого, нарушения схемы JSON и ошибки форматирования времени. Все данные были вручную верифицированы на соответствие спецификации.

### 2. Написание документации и отчётов
Черновики `README.md`, `AI_USAGE.md` и итогового отчёта подготовлены с помощью LLM для соблюдения единого стиля оформления. Финальная редакция выполнена самостоятельно с проверкой фактической точности всех утверждений и соответствия требованиям задания.

## Принципы работы с AI в проекте

-   **Доменная логика:** Модели данных, алгоритмы валидации, хеширования и обработки конфликтов разработаны без участия ИИ.
-   **Проверка результатов:** Весь код, предложенный ИИ, проходит обязательный code review и покрытие тестами перед интеграцией.
-   **Безопасность данных:** В запросы к ИИ не передавались реальные персональные данные студентов или конфиденциальная информация. Использовались только синтетические примеры.
-   **Критическое отношение:** Рекомендации ИИ рассматриваются как гипотезы, требующие экспериментальной проверки. Архитектурные решения принимаются на основе требований задания и лучших практик инженерии ПО.

## Ограничения текущего этапа

На данном этапе конфигурации режимов `ml` и `llm` возвращают детерминированный базовый результат. Реальные вызовы моделей машинного обучения или больших языковых моделей не выполняются. Интеграция внешних API и подготовка признаков для обучения запланированы на последующие этапы разработки системы.
